# 改造过程与版本演进

本文件归纳本次单台 PW2 改造的决策与证据，不是通用 Kindle 刷机史。研究平台后端独立运行，客户端通过公开接口取数。

## 1. 从“平板化”收敛到科研信息屏

最初设想浏览网页、看资讯和写作，随后目标明确为美观展示科研内容、半小时检查一次、启动即显示、Mac 关机后仍可更新。没有采用未经验证的完整替换系统镜像；最终选择保留 Kindle 底层系统与驱动，安装可恢复的原生开机科研屏。

完成越狱与兼容性检查后，先制作 Python + Pillow 的报刊式灰度原型。Mac 浏览器预览验证了版面，但不能证明 Kindle 浏览器兼容，更无法满足脱离 Mac 独立运行，因此转向 Go 原生客户端。

## 2. 原生取数、排版与开机接管

在 PW2 上验证 HTTPS、中文字体、内存和 FBInk 显示，再以 Upstart 服务接管全屏。安装流程加入设备与固件检查、文件校验、备份、接管探测、退出恢复和一次重启验证。系统修改范围限于项目拥有的启动配置。

曾出现 Start 后白屏并退回主页。检查发现 USB 物理连接标志可能在拔线后仍保留旧值；改用 `volumd` 的用户盘状态与实际挂载检测，并保留退出记录，避免把错误判定为真实 USB 接管。

## 3. 从信息墙到可阅读的“知新”

中文刊名定为“知新”，加入知识库网址、光谷天气和不突兀的“主页”按钮。栏目独立标注源数据更新时间，避免误把旧简报看成客户端未刷新。标题接入详情，继续增加翻页、下一篇和“继续读”，阅读位置保存在设备。

## 4. 长时运行与电源问题

0.5.1 修正设备电源信息对象/数组格式差异，避免漏记外接电源状态。只有明确未充电、未接 USB 电源且采样连续的同一会话，才能用于连续断电运行统计。最初观察到 13.5 小时电量从 100% 降到 21%，尚不能称为一天续航。

0.5.2 加入空闲两分钟关闭前光、点击与退出恢复原亮度、降低部分系统查询频率、首页电量显示，并改进日志轮转、低电量退出原因与恢复结果。系统在 20% 电量时退出属于策略行为，不能当作崩溃。

## 5. 实验室品牌

0.5.3 将实验室提供的 UrbanComp 标志内嵌到客户端，首页采用标志、刊名与知识库网址，加入品牌启动页与阅读页页脚。灰度墨水屏保持标志轮廓，未将实验室原始图形改画成新的标志。

## 6. 0.5.4 与完整一天验证

0.5.4 复用单轮 HTTPS 连接、结束后关闭空闲连接，将挂载轮询调整为约 2 秒，触控改为事件等待，并增加 goroutine、GC 和来源错误观测。

2026-10-31 19:40 至 11-01 21:40（北京时间），同一会话连续断电运行 **26 小时**，电量 98% → 21%，53 次更新全部成功，显示错误为 0；21:41 在 20% 退出，恢复结果成功。应用平均 CPU 占用 1.859%；此前 0.5.3 观察值约 7.54%，但这不是相同网络、亮度和使用方式下的受控对照，不能将全部电量差异归因于代码修改。

## 7. 仓库归档

将最终客户端、历史浏览器原型、安装恢复流程、自动化测试、品牌截图和脱敏性能数据分离整理。新增固定 Go 工具链检查、跨电脑构建入口、安装包白名单与 CI；Python 原型默认改用随仓库授权分发的字体。保留实测对应的原生应用逻辑，未在归档过程中给设备追加新的运行改动。

## 8. 首次公开整理

公开版本采用 MIT 许可发布原创代码、文档与合成测试数据，标志及第三方素材分别说明权利。完整上游接口快照替换为可重建的原创示例，保留原有解析、选文和长文排版测试用途；真实 26 小时遥测不变。早期私有归档在本机另存，公开分支从整理后的首版提交开始，提交邮箱使用 GitHub noreply。
